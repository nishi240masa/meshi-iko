## テンプレート
日本語の Markdown で出力する。見出しの追加・削除・名前の変更はしない。該当するものがないセクションには「なし」と書き、セクションは消さない。テンプレートの前後に前置きやまとめを書かない。

## 「5. 指摘の詳細」の記入例
ファイルは実在のものを使っているが、指摘の内容は架空。

### R-001 [issue (blocking, design-docs)] 投票状態APIのレスポンスに設計にないフィールドが追加されている
- 重大度 / 確信度: high / 0.95
- 場所: `back/internal/interfaces/handler/poll.go:40-55`
- 根拠: ハンドラが `closedAt` を返しているが、`back/api/openapi.yaml` の `Poll` スキーマと `docs/DesignDoc.md#7. アーキテクチャ・データ設計` にこのフィールドはなく、どちらもこの差分で変更されていない。
- 問題: 仕様にないフィールドを返しているため、openapi-typescript が生成するフロントの型と実際のレスポンスが一致しない。docs-first のルールにも反している。
- 影響: フロントがこの値を使い始めると仕様外の依存が生まれ、後でバックエンドを変えたときに型チェックで検出できない。
- 修正の方向性: 先に `openapi.yaml` と設計ドキュメントにフィールドを追加して合意を取り、コードを再生成してから実装を合わせる。不要なフィールドであればレスポンスから外す。

### R-002 [issue (blocking, security)] 回答の登録で回答者をリクエストボディから決めている
- 重大度 / 確信度: critical / 0.9
- 場所: `back/internal/interfaces/handler/answer.go:30-45`
- 根拠: `PUT /answers/me` がボディの `userId` で回答者を決めており、セッションから得た userID を使っていない。`docs/DesignDoc.md#7. アーキテクチャ・データ設計` は「回答者はトークンから特定する」としている。`back/internal/interfaces/middleware/auth.go` は認証だけで、回答者との照合はしていない。
- 問題: ログイン済みの利用者なら、`userId` を変えるだけで他人の回答を書き換えられる（BOLA）。設計にも反している。
- 影響: 全利用者の回答が第三者に改ざんされうる。
- 修正の方向性: 回答者はミドルウェアが特定した userID だけから決め、リクエストでは受け取らない。`openapi.yaml` の `PutMyAnswerRequest` に `userId` が紛れ込んでいないかも確認する。
